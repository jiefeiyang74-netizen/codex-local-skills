# 录音稿准备与剪映分段

## 抖音链接作为稿件输入

数学视频制作上下文中的抖音 URL 或完整分享文本，直接按[抖音输入流程](douyin-transcription.md)调用已有本地服务提取原稿，无需用户额外说“提取”或手贴逐字稿。保留原始转写、源音频、下载链接/本地路径和来源关联，再进入本文的数学验算及写稿模式；原创重构沿用既有规则，用户明确轻改或保留原稿等要求优先。原稿提取完成不等于录音定稿完成，也不等于视频制作完成。

稿件通过核查后，主动交付每段≤500字符的可复制块和编号 TXT，完整稿内部保留用于校验与对齐；按下文“配音来源与授权”取得正式配音后，工作台再按真实配音制作动画、视频和双封面，成片交付只附锁定完整最终稿。源视频提取音频仅是来源核对材料，不自动填作改写稿的正式配音，不因已有源音频而跳过正式配音这一步。等待回传期间继续独立验算和语义分镜，不伪造时间对齐或完成状态。

## 写稿模式与原创重构

写稿前依据当前明确指令及已有会话，注明采用“原稿保留”“纠错轻改”或“原创重构”。用户明确只轻改时优先遵从，只修必要错字、病句、衔接和数学错误，不强制换结构；要求保持原稿时保留措辞，数学冲突另列待决。用户提供他人逐字稿并表达原创发布意图或搬运担忧，且未明确限制为轻改时，采用原创重构；已有重构授权直接执行，不重复问。只有仅说“改稿”且上下文无法判断幅度时，集中简问一次。

原创重构按以下顺序执行：

1. 从材料抽取可核对的数学知识、题设、定义域、必要条件和结论，独立验算；区分已核实条件与本期补全假设，不为迎合原稿答案暗改题意。
2. 脱离原句式，重新设计开头、叙述主线、解释顺序、合适的新例题及关键动效；新例题独立验算，不仅同义替换或换数字，不删掉必要数学点。用户锁定的题目、开头及其他约束优先；锁定处有数学冲突时单独说明，不静默修改。
3. 交付前对照原稿自查结构、举例和解释是否实际重构，简述保留的知识点、重新设计的部分及受锁定约束保留的内容。共同数学公式、术语本身不作为照搬证据；不得凭字数或文字相似率保证平台原创审核、查重通过或原创认证。若实际只完成纠错，明确标为“纠错稿，原创重构未完成”，继续完成已授权重构，不把它交成可直接录音的原创定稿，避免用户误花录音时间。

## 输入审稿门禁

适用于保留原稿、纠错轻改和原创重构；先保留输入版本，再完成以下核查，未解决的关键冲突不得标为可录音定稿或推进依赖它的制作：

输入为乱码较多的 ASR 或方法清单时，先分清可恢复事实与不可恢复片段，保留用户明确的方法数量和核心主题，不靠猜测补成“原话”。按已有改写授权为每项补一个原创、题设完整且可验算的小题，展示关键推导与结论；只保留名称的项须明确降级为目录，不能用索引幻灯片冒充逐项讲会。锁稿及制作音频前，逐项检查定义域、变形等价性、最值可达性，以及多步不等式的等号条件能否在原约束下同时满足。交付时明确区分“重构原创例题”与“原稿恢复”，标明补写和未恢复部分，不把推测当成原稿事实；用户仅授权保留或轻改时，按既有写稿模式处理，不擅自扩大重构范围。

- 检查整段重复及疑似拼接重叠，区分有意复述与误重复；识别 ASR 同音误字、术语、字母、数字和符号疑点，有音频时按来源分流核对；满足下述锁定稿生成音频前提时，不再逐词核听。不能只凭数学推断把转写疑点定为口误；无原音或无法核实时注明未决，不伪造听审。
- 提取题设、所求及必要条件，检查缺失或自相矛盾之处。按已有授权纠错或补全并注明假设；会改变题意且尚无授权的关键缺口集中询问，不为凑出预期答案暗改条件。
- 独立验算关键公式、推导和题中每个例子，不以原答案作依据；检查分母非零、退化情形、表达式变形前后定义域及等价性、图像与口播一致，必要时回代或用边界反例核对。具体公式、数字和推导留在项目，不扩写为题型教科书。
- 纠错记录原文位置、修改前后、理由与验算依据，区分文字纠错、数学纠错和补全假设，并标明音频影响。仅转写有误而原音正确，无需重录；实际录音需改时列出受影响句段及衔接范围，有可靠时间证据才标起止秒数，不能无依据要求整段重录。修订音频后重新核对完整稿并更新受影响的对齐、审计绑定，保留旧输入。

## 录音前交付与阶段状态

先完成完整稿校验、题目与独立验算，以及简短修改或重构说明和语义分镜（讲解目标、画面、关键动效，不编造音频秒数）。完整稿内部保留用于版本校验和后续音频对齐。只要本次交稿意图让用户录音或生成音频，包括“先给稿，等用户回传音频”，就在这次回复主动给出每段≤500字符的独立可复制块和编号 TXT，不等用户再次要求分段；录音阶段默认只交分段块和编号 TXT，完整稿内部保留，用户明确索要完整版时才另提供，不能只交整稿。仅用户明确纯讨论、只审稿或不要做时，不强制提供录音分段。存在关键未决冲突的版本仍标建议稿，先解决冲突，不引导用户录制未经核准的内容。最终视频成片交付时，口播稿只提供与实际音频一致的锁定完整版链接或完整正文，不附录音分段。注明改写模式、本期补全假设与未决项；非重构模式只简述实际修改范围。真正需要用户选稿或决定关键未决项时才集中询问一次；已明确批稿或提供与定稿对应的音频，不重复要求批准。

建议在项目交付记录中使用 `review_ready → script_locked → audio_verified → preview_reviewed → final_reviewed`：分别表示稿件已自查可审阅、稿件已明确锁定、音频与锁定稿的关联及技术检查有证据（适用下述来源确认流程时不要求逐词听审，确认方式另记）、当前低清画面已真实审阅、当前高清画面已另行真实审阅。阶段名不能替代交付意图判断：即使记录为 `review_ready`，只要交稿后期待用户录音或生成音频，就必须主动分段；不得机械标为审阅阶段来避开500字符限额。它们是阶段记录约定，不是新增 runner 字段，不替代现有数学、音频、媒体或视觉验收；无对应证据不提前推进状态。

用户已授权改稿时可从当前阶段返回稿件准备，保留旧输入和版本；稿变后重新核对音频，旧音频不能冒充与新稿匹配。仅转写纠错且录音实际匹配时可保留音频，否则说明需与新定稿匹配的音频；依赖用户提供时明确该依赖，继续不依赖音频的验算和语义分镜，不擅自替换音轨或伪造对齐。

## 剪映分段与数学核对

二次函数弦间线段最值原稿：先固定弦端点，明确动点区间与抛物线开口方向，以非负长度建式。铅垂线段的中点结论指弦中点或弦端点横坐标的平均值，不能等同于抛物线顶点；斜段或垂距取最大时，弦上交点不一定是弦中点，应跟踪抛物线上端点的横坐标。改用垂距、水平距离或斜距前，须证明替代长度与原长度在同一可行域内成不随动点变化的正常数倍，才可共用极值位置；区分含延长线的直线与有限线段、射线，核对交点是否落在指定范围，排除平行或重合导致无唯一交点的情形。多条线段总长度的平均位置结论须固定各条抛物线上端点的相对横坐标偏移，依下述取等规则核对无约束极值能在共同可行域内取到；不能只凭条数或平均值宣称一般最优。混合方向或不同权重须重新建式。删去“秒杀所有题型”等无依据外推；单题数字、证明及反例留在项目。

原稿引用却未提供的图片、题干或练习，不能假称已识读原题/教材；需要补例且已有授权时，明确标注“新编例题”，补齐条件并独立验算。具体题目、数字和反例验算留在项目，Skill 只保留核查规则。

- 转写疑点、题设冲突及补全假设按上文输入审稿门禁处理；用户已明确授权的修订不重复询问，未获确认且会改变题意的版本保持“建议稿”。
- 极值题既要验证上界或下界，也要验证原约束下能否取等，不能仅凭平方不等式声称最大值或最小值；录音稿保持精简，完整取等验算可留在“题目与验算”和画面中，不强制加长旁白。
- 交稿用于用户录音或生成音频时，主动分段，每段默认硬上限 500 字符。汉字、英文、数字、标点、空格、换行均计数：保守按 UTF-16 码元计算，单独 LF 按 CRLF 两码元计，非 BMP 字符计两码元。用户明确指定其他平台限额时可用 `--max-chars` 指定。
- 优先按章节、题型及语义段落分段，其次按句界；片头归首段，片尾归末段。不得拆公式、字母下标，不得为凑限额漏字或改写。无安全边界的超长句或公式应明确报错并等待人工确认改稿。全文未超过上限时无需强制多段。与录音稿无关的回答不受此限制。
- 使用已有 Python 运行 `scripts/split_narration.py --input 完整稿.txt --output-dir 分段目录`，无新增依赖。工具保留全部原字符，输出编号 UTF-8 TXT、独立代码块的复制用 Markdown 和清单 JSON（保守字符数、原稿 SHA256、顺序拼接一致性）。不同内容的已有输出拒绝覆盖。
- 每段的“第1段/共N段”和真实字符数放在复制块外，正文各自独立代码块及 TXT。交稿用于录音时主动交付各段可复制正文与编号 TXT 的绝对路径，完整稿内部保留供对齐，仅用户明确索要完整版时另提供；精确保留末尾空白和换行以 TXT 为准。
- 保留完整逐字稿作为后续音频对齐输入；多段音频按明确段序整理，先核对全文覆盖，并保留原音频。不把分段文本当作实际语音时间，不声称当前 runner 已支持未实现的音频拼接。
- 500 字符分段用于用户录音或剪映等工具生成音频，不自动当作分镜切场，也不额外插入片头、片尾或停顿；视频仍以完整稿和实际音频连续对齐。

## 图片题：核图、精简题面与口播

- 先区分已知条件、求解目标、图中约束与装饰背景；题目未另填时从图片及已有逐字稿提取，不要求重复提供已明确的信息。长度、单位、角度、端点、范围及图上关系须逐项核对，不把示意比例当作已知条件。
- 阴影题先数清目标块数，再逐块说明边界由哪些线段、圆弧及端点围成，辨明目标是整圆、扇形、弓形或其他区域；不能按选项倒推题意，也不能把全部外侧或未标明区域当成目标。图文冲突或边界辨认不清时只询问影响结论的关键缺口，保留不确定性。
- 按用户要求删去铺垫、广告和与解题无关的情境，但保留影响数学模型的长度、单位、角度、端点、范围及对应关系；先核对删除前后约束等价，再精简措辞。若情境承载约束，转述为简洁数学条件而非直接删除。
- 分开交付精简题面、独立验算、可直接录音的口播。验算不依赖选项或预期答案，核对所求区域、单位和取值范围；详细推导留在验算区，避免全部塞入口播。
- 口播沿用已确认的语气与用户锁定开头，不强行复制煽动、夸张或与解题无关的开场。用户未锁定开头时，首句优先写紧扣本题真实信息差的问句钩子，后文必须兑现这个问题，首屏画面同步指向问句所说对象；问句服务题目，不为制造悬念夸大或改动数学。账号讲题人已有自称（如“老师”）时可自然保留，不以主语错位或多一两个字为由删去，也不要求每句使用；钩子效果以实际数据为准，不预先断言能改善留存。最终视频交付的口播使用完整版；此前交稿意图让用户录音或生成音频时，按本文既有计数规则主动提供每段≤500字符的可复制块和编号 TXT。没有对应原音频时先交稿，不编造词级时间、动作秒数或可运行时轴。

## 配音来源与授权

默认由用户按交付的分段稿生成或录制配音并回传。用户已授权代理生成配音（本地 TTS，或在用户电脑上操作剪映等配音工具）时，直接按授权执行，不再把配音无条件交回用户；用户指定的工具、音色或收藏声线优先，复用已定稿且仍与锁定稿一致的有效音频。Skill 不授予屏幕操作、登录或付费权限，本执行器也不能自行控制剪映：实际操作取决于宿主当前提供的电脑操作能力及许可；缺少能力、需首次屏幕许可、登录或付费时，如实说明具体依赖，只请用户完成该步。不自动把音频上传到外部服务。

生成后先核对：音频段与分段稿编号一一对应，无漏段、重复段或多轨叠加，按段序拼接后整体可解码、时长合理，再进入对齐。原视频源音频只读，不拿来冒充新稿配音。

## 用户明确授权本地 TTS 时：连读与停顿

用户已明确授权本地 TTS 时，按既有授权生成配音，替代默认的用户自行生成并回传环节；不自动替用户上传音频至 TTS 服务。以完整语义句作为连读单元，逗号、冒号、顿号默认不作为强制切分点，数学表达不拆散；录音稿字符限额不直接充当引擎切分规则。

检查实际适配器与引擎的切分、拼接行为，将显式添加的尾静音与自然语音停顿分开。仅可精确缩短有来源及边界证据的填充静音，保留自然停顿与字音；不得全局删除低能量或静音区间，以免吞字。仅在自行 TTS 发现问题或用户反馈时，用受影响的代表性数学句生成短样，核对连读、字音完整性与填充边界；复用已接受且仍适用的配置，不为每条录音新增试听确认。

音频变更沿用本文版本核对与动作审计规则：保留原音，重新对齐并重建 timeline、绑定与动作审计，按既有预览/成片流程完成新版本 QA；不得直接替换旧视频音轨或套用旧 QA。语速、音色及本期路径、诊断数据留在项目，不写入通用规则。

## TTS 数学标签读音与文本映射

仅在自行 TTS 发现读音/停顿问题或用户反馈时，用受影响的短样例修复并复用已接受的读法，不给每条录音增加试听门禁；下文锁定稿来源确认规则不变。某些 GPT-SoVITS 英语分支会给不足 4 个 phoneme 的短片段补 comma，中英混合字母组因此可能产生额外停顿；逐字加空格或删除人工 comma 不保证改善，失败方案不反复套用。读法与音色由项目显式选择，不把某台机器的音色、字母音译或一次试听结果变成通用默认，也不声称消除所有停顿或发音自动验证通过。

正式 display/canonical 稿保留原字母，只在 TTS spoken 层转写明确标记的数学对象。组内不自动插入空格或标点，完整标签的读法由配置提供。保存原稿、spoken、配置、source span 和哈希；同名词可能兼作英文时使用 occurrence span，不用全局字符替换。未标记标签与普通英文保持原样。

使用已有 Python 执行 `scripts/prepare_tts_readings.py --input display.txt --readings readings.json --output-dir tts-text`。纯标准库工具只输出 `spoken.txt` 和 `reading-map.json`，不调用 TTS、不修改原稿、不生成时间。配置二选一：

- `{"labels":{"P":"皮","PQ":"皮丘"}}`：示意读法，必须换成项目选定读法；字典声明这些完整数学标签的所有出现均可转写。最长完整标签优先，区分大小写；支持 ASCII 字母开头的字母/数字/下划线标签，中文可紧邻标签。不会把普通单词里的单个字母当标签，也不自动把未列出的组合拆成已列出的单字母。
- `{"spans":[{"start":1,"end":3,"label":"PQ","reading":"皮丘"}]}`：对原稿“线PQ长”只标记这一处。区间为从零开始、左闭右开的 Python Unicode 码点索引，不是 UTF-8 字节或 UTF-16 码元；保留 BOM、CRLF、非 BMP 字符及组合字符，不做 Unicode 归一化。拒绝重叠、越界、子串和原文不匹配的 span。

映射按原稿顺序连续覆盖 display 与 spoken，含 identity/label 段及两侧原文，可重建原稿。标签替换是区间对应，不表示多码点读音与字母逐字一一对应；工具不推断数学语义。不同内容的已有输出拒绝覆盖，应换新输出目录。

## 锁定稿生成音频：来源确认替代逐词追问

仅当口播稿由本 Skill 提供并已锁定，且用户已明确表示本次音频按该版本生成时适用。记录锁定稿与原音频 SHA-256、用户声明的会话来源及其对应版本；已有明确声明直接复用，不再次询问，也不把仅收到一个音频文件当作按稿生成声明。

此前提下，以锁定稿作为内容依据，保留原音；跳过逐词人工听辨，不因 ASR 同音误字、字母/数字漏识别或低置信度反复追问、要求重录或阻挡渲染。仍全量解码音频，检查时长与首尾、章节覆盖、声道和技术完整性，并以真实音频做动效自动时间对齐。仅在有可核查证据证实整段缺失、文件损坏或重大内容错配时处理受影响部分；ASR 低匹配、漏词或同音分歧本身不构成这类证据。

内容来源确认不豁免时间对齐：保留真实原始 token、时间、来源与不确定性，不能按字数插值、改写 token 或伪造审计通过。有效锚不足时复用或补充局部真实时间证据，修复自动对齐；这是技术待修项，不能转成逐词听辨确认门槛，也不能绕过 runner。技术检查与动作审计通过后，ASR 内容不确定性仅作非阻断记录，继续预览与成片流程。

用户声明记为 user-reported 来源证据；未实际听审不得写成人工听审通过，也不推断用户逐秒听完。此规则不替代数学审稿或低清/高清视觉验收。来源不满足前提时按原音与原稿核对疑点，注明未决，不把 ASR 当作听辨；稿件或音频版本改变后重新核对关联，不能套用旧版本声明，已有覆盖新版本的声明无需再问。

## 其他来源或未确认对应锁定稿的已有音频：决定是否需要重录

先保留原音频并记录内容哈希，把原稿、修改建议、实际录音核对结论分开。画面公式采用已验算的表达，不把转写错字直接上屏；request.narration 应对应本次音频，不能把未录制的新稿冒充原音内容。

- ASR 漏负号、字母、分母或术语时，先核对局部上下文；必要时截取该段作本地重新识别或听审。再次识别仍不等于听到原音，记录范围及剩余不确定性，不把识别遗漏定性为口误，也不以数学推断改写原 token。
- 仅文字转写错误而录音内容可确认匹配时，无需重新生成音频。确认录音存在影响结论的数学错误时，说明具体位置及影响，使用已有授权修复；未获覆盖时让用户选择重录相关内容或明确保留并在画面纠正，不能静默交付相互矛盾的声音与结论。
- 原始 alignment 保留；局部重识别结果作核对附件。改变正式音频、稿件或锚点数据后重建绑定与动作审计。零长度、越尾等无效 token 保留无效状态，不插值补成词级时间。
- 无法听审时，可继续不依赖该疑点的验算与画面制作；影响关键条件的未决疑点单独标记，最终说明实际核对范围，不宣称人工逐字听审或精确逐词同步。
